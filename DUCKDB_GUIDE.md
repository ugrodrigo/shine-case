# Using DuckDB for the Shine case

## What is included

- `shine_case.duckdb`: the local database generated by the EDA runner.
- `sql/shine_eda.sql`: the complete, reproducible SQL analysis.
- `sql/kpi_deep_dive.sql`: funnel, revenue inactivity, pre-activation closure,
  revenue, observed-LTV, and acquisition queries with segment breakdowns.
- `sql/cohort_state_analysis.sql`: activation-cohort state distributions and
  state transitions at each month of customer age.
- `sql/cohort_playground.sql`: a short cohort query designed for editing.
- `sql/streak_analysis.sql`: consecutive revenue-activity and loyalty analysis.
- `sql/streak_playground.sql`: a short editable persona loyalty ranking.
- `sql/revenue_concentration_analysis.sql`: top-10 and top-20 revenue
  concentration, segment mix, and tenure-controlled sensitivities.
- `sql/concentration_playground.sql`: editable top-20 concentration sensitivity;
  do not use it as the primary full-population segment ranking.
- `sql/playground.sql`: a small query template intended for experimentation.
- `run_eda.py`: rebuilds the database and exports the EDA result tables.
- `run_query.py`: runs the playground or another SQL file.
- `eda_outputs/`: CSV results that can be opened in Excel or used for charts.
- `COHORT_STATE_FINDINGS.md`: state definitions, cohort results, caveats, and
  interview questions.
- `STREAK_LOYALTY_FINDINGS.md`: whether streaks add information and which
  personas and plans have the strongest revenue continuity.
- `REVENUE_CONCENTRATION_FINDINGS.md`: top-decile share, population coverage,
  revenue types, segment mix, and tenure caveat.
- `FINAL_PRESENTATION_KPI_FRAMEWORK.md`: recommended case thesis, formal metric
  glossary, selected and excluded KPIs, and a three-slide structure.

## Run the full analysis

From the project folder:

```powershell
python run_eda.py
```

This reads the two source CSVs, creates typed DuckDB tables, executes all EDA
queries, and refreshes the files in `eda_outputs/`.

## Current analysis cutoff

Core EDA tables use April 2026 as the confirmed cutoff. May remains in the
monthly trend output with `analysis_status = 'provisional sensitivity'` and has
a separate `eda_may_coverage_check.csv` diagnostic.

- Funnel outputs exclude the incomplete May signup cohort.
- Persona and initial-plan snapshots use April.
- Cohort, missing-month, concentration, and outlier calculations stop in April.
- Change `confirmed_end_month` in the `analysis_parameters` table definition at
  the top of `sql/shine_eda.sql` if May is later confirmed as complete.

## Try your own SQL

1. Open `sql/playground.sql`.
2. Change the query and save the file.
3. Run:

```powershell
python run_query.py
```

You can also create another SQL file and pass its path:

```powershell
python run_query.py sql/my_question.sql
```

The query runner opens the database in read-only mode, so exploratory queries
cannot accidentally overwrite the prepared tables.

## Segment KPI outputs

The most useful starting point is `eda_outputs/eda_segment_scorecard.csv`. It
combines funnel, pre-activation closure, April revenue-activity transitions,
sustained inactivity, April revenue, new-company volume, and the age-three
observed-LTV proxy for every persona and initial plan.

Detailed outputs are also available for:

- 30-day funnel by signup cohort and segment.
- Monthly revenue-company dropouts, retention, and reactivation by segment.
- Monthly confirmed two-month revenue inactivity incidence by segment.
- Sustained one-, two-, and three-month revenue inactivity by segment.
- Empirical return probability after each inactive month.
- Active, At-risk, and Churned-proxy states by segment and revenue type.
- Post-activation account closures as a separate descriptive output, not churn.
- Monthly revenue by persona, initial plan, and revenue type.
- Observed-LTV proxy by activation cohort, age, segment, and revenue type.
- New-company trends by signup month and segment.
- Activation-cohort state matrices and state transitions at equal customer age.
- Consecutive revenue-active streaks, strict continuous-activity shares, and
  next-month persistence after a streak has restarted.
- Cumulative and tenure-controlled top-10 and top-20 revenue concentration.
- Preferred top-20 concentration across the first three complete calendar
  months after activation, excluding the partial activation month.
- Presentation account-health states combining lifecycle continuity with a
  trailing-three-month revenue-momentum warning.
- Revenue-decline threshold sensitivity and high-value Watch accounts by
  persona and initial plan.
- Transparent full-population persona and initial-plan opportunity rankings
  plus comparable mature-company health stacks. Top-20 composition remains a
  secondary concentration view.

## Run and adapt the cohort analysis

Rebuild all tables first, then run the cohort template:

```powershell
python run_eda.py
python run_query.py sql/cohort_playground.sql
python run_query.py sql/account_health_playground.sql
```

Use `months_since_activation` to compare cohorts at the same age. For example,
age 3 compares every eligible cohort in its fourth calendar month after
activation. Do not compare each cohort's latest available month directly,
because older cohorts have had more time to become inactive.

## SQL concepts used in the analysis

- `JOIN ... USING (company_profile_id)` combines company attributes with revenue.
- `GROUP BY` chooses the reporting grain, such as one row per month or persona.
- `COUNT(DISTINCT ...)` counts companies instead of revenue rows.
- `SUM(...)` aggregates the four revenue streams.
- `FILTER (WHERE ...)` calculates conditional counts.
- `DATE_TRUNC('month', ...)` creates monthly cohorts.
- `DATE_DIFF('month', ...)` calculates customer age in months.
- `LAG(...) OVER (...)` compares a month with the previous month.
- `NULLIF(..., 0)` prevents division-by-zero errors.

## Recommended SQL appendix for the three-slide case

Do not paste the entire EDA into the slides. Put the complete SQL file in the
submission appendix, then show only the queries supporting the key claims:

1. Preferred three-complete-month concentration and BTP composition.
2. Revised high-value health states and the revenue-decline threshold
   sensitivity.
3. The cohort or segment comparison behind the recommended initiative.
4. Optionally, the missing-month, May-completeness, or negative-fee validation.

Keep comments explaining definitions and assumptions. This is more valuable
than including every exploratory query.
